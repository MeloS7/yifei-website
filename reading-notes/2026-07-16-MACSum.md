# MACSum：第一个"混合属性可控摘要"的人工标注数据集

## 论文信息

- **标题**：MACSum: Controllable Summarization with Mixed Attributes
- **作者**：Yusen Zhang（宾州州立，微软实习期间完成）、Yang Liu（微软研究院，通讯）、Ziyi Yang、Yuwei Fang（微软）、Yulong Chen（西湖大学）、Dragomir Radev（Yale）、Chenguang Zhu、Michael Zeng（微软）、Rui Zhang（宾州州立）
- **发表**：**TACL 2023**（Transactions of the ACL, vol. 11, pp. 787–803）
- **链接**：[aclanthology.org/2023.tacl-1.46](https://aclanthology.org/2023.tacl-1.46/) · [arXiv:2211.05041](https://arxiv.org/abs/2211.05041) · [代码与数据](https://github.com/psunlpgroup/MACSum)
- **一句话总结**：可控摘要一直缺少真正的人工标注数据（大家都是把通用数据集"改造"成伪可控数据），本文构建 MACSum——让 4 位标注者针对**同一篇原文的多组不同属性组合**分别手写摘要，覆盖 5 个属性（Length / Extractiveness / Specificity / Topic / Speaker）、两个领域（新闻 + 会议对话），共 **8333 条摘要 / 1353 篇原文**；并给出 hard prompt 与 soft prefix 两个基线和两个新指标（CER / CC）。结论是：**hard prompt 最好，但混合属性控制仍然远未解决**。

---

## 1. 解决的问题

可控摘要（controllable summarization）想让用户定制摘要——要短的、要抽取式的、只讲某个话题的。但这个领域有两个结构性问题：

### (1) 没有真正的人工标注数据，大家都在用"伪数据"

现有工作只能把通用摘要数据集**改造**成可控数据。论文举的例子很典型：He et al. (2020) 从一个通用摘要里**反向抽取话题**，然后假装"这个摘要是被这些话题控制着生成的"。作者指出这种做法有三个硬伤：

1. **这些摘要根本不是在属性指导下写出来的**——是先有摘要，再倒推属性
2. **每个原文只能配一个目标摘要**，但可控摘要的本质恰恰是"同一篇原文、不同属性 → 不同摘要"
3. **像 Extractiveness、Specificity 这种属性，压根没有直观的改造方法**——你没法从一个现成摘要里"反推"出它当初被要求多抽取式

我觉得**第 2 点是最要害的**：如果每个原文只有一个参考，你根本无法把"控制信号的作用"和"这篇文章本来该怎么摘"分离开。这是伪数据的原理性缺陷，不是数据量能弥补的。

### (2) 大家只控制单个属性，混合控制没人做

以前的工作各自专精于长度、实体、方面、内容、风格、粒度、抽取度……但真实用户的需求是**同时**的："给我一段**短的**、**高度抽取的**、**只讲 Pope Francis** 的摘要"。论文的 Table 1 对比得很清楚——MACSum 是唯一同时满足 **人工标注 + 同源多输出 + 混合属性 + 覆盖对话与文档** 的数据集。

## 2. 五个控制属性

| 属性 | 取值 | 定义 |
|---|---|---|
| **Topic (Tpc)** | 关键词（可多个） | 摘要只应包含与给定话题相关的内容 |
| **Speaker (Spk)** | 说话人名（可多个，仅对话域） | 只关心指定说话人说了什么 |
| **Length (Len)** | short / normal / long | 摘要词数（服务于用户的阅读时间预算） |
| **Extractiveness (Ext)** | normal / high / full | 摘要中直接抽取自原文的比例 |
| **Specificity (Spe)** | normal / high | 细节/描述性内容的**密度**（数字、实体、人名等） |

**Spe 与 Len 的区分是这篇的一个思考点**：Length 是词数，Specificity 是描述性内容的**密度**——所以**一个短摘要完全可以比长摘要的 specificity 更高**。这个区分本身是对的（沿用 Louis & Nenkova 2011 的思路）。但后面会说到，**他们实际用的 Spe 度量把这个区分给破坏了**。

## 3. 标注流程

四步（Figure 2）：

1. **原文选取**：文档域用 **CNNDM**（从 test set 随机取 10k 篇）；对话域用 **QMSum**（按话题切分成短单元，丢弃 >5000 token 的）
2. **候选属性抽取**：Topic 用关键词抽取工具（pke, Boudin 2016）取 **top-20 关键词**做候选；Speaker 收集原文所有说话人；**Len / Ext / Spe 从均匀分布里随机生成**，论文说是为了"模拟用户多样化的需求"
3. **属性生成**：雇 **4 位英语母语标注者**。Topic 可以从候选里选，也可以自己写关键词；Speaker 从候选里挑一个或多个；Len/Ext/Spe 自动随机填。**每个原文每 2000 词大约生成 8 组样本**
4. **摘要撰写**：标注者先读指南和 10 个示例，然后针对每组属性组合各写一条摘要。**还要额外标注"相关文本片段"**（产出这条摘要所必需的最小 turns/句子集合）和**一个摘要标题**（论文说标题还有个副作用：可以快速验证标注者是否真的读了自己写的摘要）

**质量控制**：(a) 试标测试——给每位标注者同样的 3 篇输入 + 各种混合属性，据此筛选合格者；(b) **每周抽样检查**并给反馈。

标注指南里的量化标准（附录 C）值得记一下：
- **Normal length** = 相关文本片段的 15–25%；**Long** = 30–35%；**Short** = 5–10%
- 而且明确说这些标准可以**动态调整**——"长度控制的目标是让不同输出的长度有区分度，如果三种长度太接近就可以微调标准"

## 5. 两个新指标

### Control Error Rate (CER，越低越好)

**CER(ŷ, y) = |f_r(ŷ) − f_r(y)| / (f_r(y) + ε)**

衡量生成摘要与黄金摘要在"控制程度"上的距离。

### Control Correlation (CC，越接近 gold 越好)

**CC(ŷ₁, ŷ₂) = (f_r(ŷ₁) − f_r(ŷ₂)) / Distance(v₁, v₂)**

衡量模型在不同属性取值下产出的分布差异。CC 大于/小于 0 表示模型与控制目标**正/负相关**。

### 属性度量函数 f_r

| 属性 | 度量 |
|---|---|
| Topic | 摘要中出现的话题关键词**比例** |
| Speaker | 指定说话人所说的 token 数 / 摘要总 token 数 |
| Length | 摘要 token 数 |
| Extractiveness | 摘要对原文的 **ROUGE-2 precision 与 ROUGE-3 precision 的平均** |
| Specificity | **(0.1×动词 + 0.2×token + 0.3×名词 + 0.4×数词) / 句子数** |

## 6. 方法与结果

### 三个基线

- **HP（Hard Prompt）**：把 `"Topic: X; Speaker: Y; Length: Long; Extractiveness: High; Specificity: High"` 这样的描述用 `;` 拼接，**直接前置到输入原文**
- **SP（Soft Prefix）**：沿用 prefix-tuning（Li & Liang 2021）。每个属性取值分配 m 个前缀向量；**混合控制时把所有取值的 embedding 相加**；前缀被 prepend 到 Transformer 每一层作为额外的 key/value。Tpc/Spk 则用话题词/说话人名的 embedding，只加在输入层
- **HP+SP**：两者结合

backbone 是 **BART-large-cnn**，8×A100，lr 3e-5。

**关键观察**：
- **HP 在几乎所有指标上都最好**——最简单的方法赢了
- **SP 和 HP+SP 在 MAC-Dial 上的 Len CC 是负的**（−0.798 / −2.034）→ **长度控制方向是反的**，你要长的它给短的
- 论文明确提醒：**CER 不可跨数据集比较**（尺度不同，例如无控制的 BART 在 MAC-Doc 的 Ext CER 是 1.177，在 MAC-Dial 是 0.544）

### 分析（§6）

- **§6.1 属性取值的难度**：MAC-Doc 上 **Len: normal 最难**（比 short/long 都难），Ext 和 Spe 都是 **high 最难**；MAC-Dial 上分别是 short / normal / high 最难
- **§6.2 属性依赖性**（我觉得这是全文最有价值的分析）：随机取 200 个样本，把某个属性改成另一个值，看**其他属性**的输出变化。MAC-Doc 上 **Len 的依赖性最强**（改 Len 会大幅影响 Ext 0.52 / Spe 0.79 / Tpc 0.48 / Quality 0.67），**Spe 最弱**；MAC-Dial 上 **Ext 最强**
- **§6.3 预训练的影响**：BART-large-cnn vs BART-large。MAC-Doc 上 cnn checkpoint **对长度控制帮助很大**（Len CER 0.315 vs 0.361）；MAC-Dial 上**几乎没差别**（0.454 vs 0.469）→ CNNDM 预训练带来的是**新闻域特有**的属性控制能力
- **§6.4 三个失败模式**（命名得很好）：
  - **Topic Defocus**：模型过度依赖"把话题词塞进摘要"，而人类标注者会做真正的高层话题概括（Case 1：gold 摘要**根本没出现 "education" 这个词**，但内容全是教育相关；模型摘要含了这个词，内容却组织混乱）
  - **Length against Specificity**：长摘要天然携带更多细节，短摘要天然低 specificity → **short + high specificity 是内在矛盾的组合**
  - **Extractiveness against Readability**：Ext: full 时生成的摘要支离破碎、不合语法，对话域尤甚。论文诚实地承认：**人类标注者被要求写全抽取摘要时，本身就不得不写出不自然的句子**

## 7. 我的评价

### 做得好的地方

1. **对伪数据三个缺陷的诊断是准确且重要的**，尤其"每个原文只能有一个目标摘要"这条。**同源多输出**（Multi-O）是这个数据集真正的价值所在——它是唯一能把"控制信号的效果"从"这篇文章本来该怎么摘"里分离出来的设计。Table 1 显示 MACSum 是唯一同时具备 Anno + Multi-O + Mixed 的数据集，这个定位是站得住的。
2. **属性依赖性分析（§6.2）是真贡献**。"混合属性控制"如果只是 N 个独立控制的叠加，那这篇就没什么意思了；他们**实际测量了属性之间的相互干扰**，并发现 Len 是 MAC-Doc 上的"主导属性"。这才是"mixed"这个词的分量所在。
3. **三个失败模式命名得好、且都是真的**。Topic Defocus / Length vs Specificity / Ext vs Readability 是可以被后续工作直接引用的概念。
4. **诚实报告负面结果**：HP+SP（他们自己提的组合方法）在大多数指标上**不如 HP 单独用**，他们照实写了，没有藏。SP 在对话域长度控制上 CC 为负也照实报了。
5. **按原文划分数据集**（而非按样本），避免了同源样本跨 split 泄漏。这个基本功很多数据集论文做错。

### 我觉得有问题的地方

**(1) Specificity 的度量函数是拍脑袋定的，而且自相矛盾。**

`f_Spe = (0.1×vb + 0.2×tok + 0.3×nn + 0.4×cd) / n_s`

这四个权重 0.1/0.2/0.3/0.4 从哪来的？论文只说"我们发现动词、名词、数词和总token数最能反映 specificity"——**没有任何证据、没有消融、没有拟合过程**。这就是四个魔法数字，而且它们是等差排列的，看起来像是随手排的顺序偏好而非测量结果。

**更要命的是它自相矛盾**：这个式子里含 `0.2 × tok`（总 token 数）除以 `n_s`（句子数）——**也就是说 f_Spe 里直接包含了"平均句长"这一项**。而论文自己在 §3.1 白纸黑字写着 *"Specificity differs from Length"*。**他们用来测量 specificity 的指标里，长度是内建的。**

这直接污染了两处结论：(a) Table 3 用 f_Spe 来"验证标注质量"（Spe: high 的样本 f_Spe 更高——可能只是因为它们更长）；(b) §6.4 的 "Length against Specificity" 现象——**这个"矛盾"有多少是真实的语言学张力，有多少只是他们自己的度量把长度算进去了？论文无法区分，因为它没有做去相关分析**（对比一下：RoSE 至少还知道要通过调 α 让归一化分数与长度**去相关**）。

**(2) Topic 的度量是浅层词汇匹配，而论文自己的 Case 1 就证明了它不成立。**

`f_Tpc = 摘要中出现的话题关键词比例`。

但 Case 1 里，话题是 "education"，**gold 摘要通篇没有 "education" 这个词**，内容却完全是教育相关的；模型摘要含了这个词，人类却判定它更差。论文把这个现象命名为 "Topic Defocus" 并当作模型的问题——**但它同时也是度量的问题**：一个纯词汇存在性的指标，根本无法区分"关于教育的内容"和"含有 education 这个词"。

而且这引出一个技术隐患：CER 的分母是 `f_r(y) + ε`。如果 gold 的 f_Tpc = 0（Case 1 就是这种情况），那 CER = f(ŷ)/ε **会爆炸**，单个这样的样本就能污染整个算术平均。**ε 的取值论文从头到尾没有给出。** Table 3 显示 Topic 的平均 f_Tpc 是 0.79–0.98，说明大部分 gold 确实含关键词——但 Case 1 证明了零值样本确实存在。

**(3) 控制其实基本没成功，而这一点被"HP 最好"的表述冲淡了。**

看绝对数值：即便是最好的 HP 模型，MAC-Doc 上 **Ext 的 CER 是 0.802**——意思是预测值偏离 gold 达 **80%**。Spe 是 0.353，Len 是 0.340。MAC-Dial 上更差，平均 CER 0.458。论文的结论"mixed-attribute control is still challenging"是对的，但我认为**措辞太温和了**：在 Extractiveness 这个属性上，控制**基本上是失效的**（HP 的 0.802 相比无控制 BART 的 1.177，改善有限）。

**(4) Gold 自己只有 73–83% 遵循控制要求——这是个天花板问题，论文却把它当成质量证据。**

Table 6 里 gold 的得分是 0.73–0.87。论文的解读是："golden summaries always rank first... 验证了 MACSum 的高标注质量"。

但反过来读：**人类标注者亲手写的、专门为满足这些属性而写的摘要，在另外两位评估者看来也只有约 80% 的时候真的满足了这些属性**。这意味着：
- 数据本身有约 20% 的噪声（相对它自己的规范）
- **模型的性能上限被这个噪声压住了**——训练数据里就有 1/5 不符合标签
- MAC-Dial 的 Ext/Spe gold 只有 **0.73**，而这两个恰恰是最难标的属性

论文完全没有讨论这个天花板的含义。

**(5) 随机分配属性组合会制造出内在矛盾的样本，而跳过率从未报告。**

Len/Ext/Spe 是**从均匀分布随机采**的，论文称之为"模拟用户多样化的需求"。但真实用户不会提出随机的组合，而且论文自己的 Case 2 就承认 **short + high specificity 是内在矛盾的**。

论文说"如果某些组合被认为太难实现，我们允许标注者在**罕见情况下**跳过"——**但从未报告跳过率**。这里有个两难：
- 如果矛盾组合被系统性跳过了 → 数据集有隐藏的选择偏差，而且"某些组合很难"这个发现被人为抹平了
- 如果没被跳过 → gold 数据里包含大量被强行写出来的、不自然的摘要（Case 3 的 Ext: full 就是明证）

无论哪种，都该量化。论文没有。

**(6) 只有 BART 一个 backbone，且完全没有 LLM 基线。**

arXiv v2 是 2023 年 6 月，论文自己也引用了 Goyal et al. 2022a（GPT-3 时代的摘要评估）。而 **MACSum 的 HP 方法本质上就是"把属性描述写进 prompt"——这恰恰是 LLM 最擅长的范式**。在一篇主打 prompt-based 控制的论文里完全不测 GPT-3.5/GPT-4，是个明显的空缺。这也让"混合属性控制很难"这个结论的适用范围存疑：**难的是这个任务，还是 BART-large 太弱？**

**(7) HP+SP 变差了，但解释不足。**

附录 A 透露了大量调参手工痕迹：要先加载 HP 训练好的模型、语言模型和前缀用不同学习率（3e-5 / 1e-6）、还要**把 Len 前缀整个删掉**。这些 hack 说明 soft prefix 在主动干扰 hard prompt，但论文除了归因于"预训练 checkpoint 已经会长度控制"之外，没有深入。

**(8) 人工评估规模很小**：2 位评估者、180 条摘要、二元 yes/no、无功效分析。Cohen's kappa 0.69–0.87 还算可以。但结合我读的 [RoSE](2026-07-16-RoSE.md) 的功效分析——30 条/模型/域的样本量，几乎不可能检测出中等大小的差异。

---

## 8. 论文自己承认的 Limitations

TACL 不强制 Limitations 章节，这篇也没有专门写。它在正文里主动承认的有：

- **混合属性控制仍然很难**，模型与人类之间存在大差距（结论段明确说了）
- **CER 不可跨数据集比较**（尺度不同）
- **Ext: full 会逼得人类标注者写出不自然的句子**，而这个现象被训练后的系统进一步放大（§6.4 Case 3）
- 允许标注者跳过太难的组合

**没有承认的**：f_Spe 的权重无依据且含长度、f_Tpc 是浅层词匹配、CER 的 ε 未定义且在 gold≈0 时不稳定、gold 只有 ~80% 自洽、跳过率未报告、无 LLM 基线。

## 9. 值得进一步探索的问题

1. **重做 Specificity 的度量**。这是我认为最该做的：现在的 f_Spe 把长度算了进去，导致"Length vs Specificity 的矛盾"这个发现无法证伪。至少应该做一次**去相关**（像 RoSE 对 nACU 的 α 做的那样），或者干脆用一个人类判断校准过的 specificity 分类器。**在此之前，这篇关于 Spe 的所有结论都该打折扣。**
2. **LLM 时代重跑一遍**。MACSum 的 HP 就是 prompting，GPT-4/Claude 这类模型在混合属性控制上能做到什么程度？这是个几乎零成本、但能立刻更新领域认知的实验。而且 MACSum 的**同源多输出**设计恰好是评估 LLM 可控性的理想 testbed——数据集的价值可能远大于论文本身的模型贡献。
3. **属性依赖性的机制**：§6.2 只测出了依赖性存在，没解释为什么。Len 在文档域主导、Ext 在对话域主导——这是模型的问题还是任务的内在结构？能否通过解耦的训练目标缓解？
4. **矛盾组合的系统性研究**：哪些属性组合是**语言学上不可能**的（short + high spec + full ext？），哪些只是模型做不到？这需要先把跳过率和标注者的困难反馈公开出来。
5. **Topic 控制的正确度量**：从词汇存在性升级到语义相关性（比如用 NLI 或 embedding 相似度判断"摘要内容是否属于该话题"）。论文自己的 Case 1 已经把问题指出来了，只差没动手。
6. **和评估协议的连接**（结合我读的另外三篇）：MACSum 的属性其实是一种**"targeted evaluation"的具体实例**——而 [RoSE](2026-07-16-RoSE.md) 的核心倡议正是"明确定义要评估的质量维度"。RoSE 发现标注者会无差别地偏爱长摘要（相关 0.833/0.875），而 MACSum 恰恰**把长度变成了一个显式的、被控制的维度**。**这两条线应该合流**：用 MACSum 式的显式属性规范，去解决 RoSE 指出的"无约束人工评估测的是个人偏好"的问题。这可能是这四篇读下来最有价值的交叉点。
