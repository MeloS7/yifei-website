# FaithRL：别再奖励"胡说八道但蒙对了"的推理步骤

## 论文信息

- **标题**：Stop Rewarding Hallucinated Steps: Faithfulness-Aware Step-Level Reinforcement Learning for Small Reasoning Models
- **作者**：Shuo Nie, Hexuan Deng（共同一作）, Chao Wang, Ruiyu Fang, Xuebo Liu†, Shuangyong Song, Yu Li, Min Zhang, Xuelong Li†
- **机构**：哈尔滨工业大学（深圳）、中国电信人工智能研究院（TeleAI）、浙江大学、中关村学院
- **arXiv**：[2602.05897](https://arxiv.org/abs/2602.05897)（v2，2026-05-27）
- **代码**：https://github.com/Easy195/FaithRL
- **一句话总结**：给"小推理模型"（1.5B 左右）的思维链做逐句忠实度打分 + 用截断重采样构造对比样本，专治"答案蒙对了、但过程全是幻觉"的强化学习奖励作弊问题。

---

## 1. 解决的问题

大模型越做越小已经是明确趋势（端侧部署、成本约束），"小推理模型"（Small Reasoning Models, SRM，作者特指 1B～2B 量级、依赖 CoT 做 test-time scaling 的模型）因此变得重要。但作者发现一个此前被忽视的现象：**SRM 比大模型更容易出现"忠实性幻觉"（faithfulness hallucination）**——不是编造客观事实（factual hallucination），而是给定一段上下文（context）后，模型的推理步骤或答案脱离、曲解、甚至编造超出这段上下文的信息。

现有主流方法是用 GRPO 之类的 outcome-based RL：只看最终答案对不对来发奖励。问题在于——**当最终答案蒙对了，但推理过程（CoT）里其实充满幻觉时，outcome reward 会把这条"瞎猜对了"的轨迹当正例强化**，模型学到的是"输出正确格式的答案"而不是"忠实地推理"。少数考虑 CoT 的方法（如 FSPO）也只给整条 CoT 一个粗粒度总分，无法精确惩罚某一步的幻觉。

论文第 3 节做了三组分析实验，把这个问题讲得很扎实：

1. **规模对比**（Table 1）：在 SQuAD/NewsQA/TriviaQA/NQ/HotpotQA 五个开卷问答数据集上，DPSK-1.5B 相对 DPSK-7B，平均 Faithful Rate 低 20 个百分点、Acc（F1）低 14.8 个百分点；Qwen3-0.6B 相对 Qwen3-8B 也有类似的显著差距。小模型确实更容易"不忠实"。

2. **CoT 比答案更容易幻觉**：用 Qwen3-32B 逐句判断 CoT 是否忠实于上下文，定义 CoT Faithful Rate。在 NewsQA 上，DPSK-1.5B 的答案 Faithful Rate 是 67.40%，但 **CoT Faithful Rate 只有 6%**——几乎每条 CoT 里都至少有一句是幻觉。为了排除"无关的过渡句也被误判"的干扰，作者进一步用一种类似树搜索的"逐句消融"方法（通过屏蔽某句、观察后续 PPL 的变化）反向定位出真正影响答案的"关键推理路径"，这条关键路径的 Key CoT Faith 是 39.11%，依然远低于答案层面的 67.40%——说明幻觉集中在真正驱动答案的推理步骤上，而不只是无关碎碎念。

3. **攻击实验证明这种不一致是有害的**：作者挑出"CoT 有幻觉但答案蒙对了"的样本，用 GPT-5.2 针对幻觉步骤反向构造新问题去"钓鱼式攻击"模型。结果 DPSK-1.5B 的攻击成功率高达 **59.48%**，Qwen3-1.7B 也有 48.75%。也就是说，这些看似"答案正确"的幻觉推理，一旦换个问法立刻现原形——不忠实的 CoT 不是无害的副产物，而是模型对上下文真实理解程度差的信号，会在其他问题上继续犯错。

这三点共同指向一个训练层面的漏洞：**只用 outcome reward 的 RL，会系统性地奖励"蒙对的幻觉推理"**，这正是 FaithRL 要修的洞。

---

## 2. 方法：FaithRL

FaithRL 在标准 GRPO 之上叠加两路互补的**逐句（step-level）奖励信号**：

### 2.1 隐式奖励：动态截断重采样（Dynamic Truncated Resampling, DTR）

核心思路：把"发现幻觉步骤"这件事，直接变成一次"重新采样"操作，天然产生对比样本。

具体流程：
1. 对第 k 次 rollout 生成的 CoT，逐句用 **HHEM-2.1**（Vectara 出品的一个专门做幻觉检测的小模型，作为 PRM/过程验证器）判断每一句是否忠实于上下文。
2. 一旦在第 t 句检测到不忠实，就把轨迹在这里截断，只保留前 t-1 句（忠实前缀），拼回 prompt，从这里**重新生成**后续内容，得到一条新轨迹。
3. 这样原轨迹和新轨迹共享同一个忠实前缀，只在"幻觉发生点"之后分叉——天然构成了一组对比数据。

论文在 4.1 节和附录 A.5 里给出了一个推导：这种截断重采样，数学上等价于给共享前缀分配两条轨迹奖励的均值，给分叉后的两段后缀分配差值奖励的正负两半。也就是说，**虽然没有显式定义"步骤奖励函数"，但重采样机制本身隐式地实现了"惩罚幻觉步骤、强化忠实前缀"的效果**。为了控制采样预算，DTR 把初始 rollout 数设为标准 GRPO 的一半（因为每条截断轨迹都会配对出一条重采样轨迹），如果某条 CoT 从头到尾都忠实、没有触发截断，就额外独立采一条样，凑齐总预算。

### 2.2 显式奖励：基于 PRM 的逐句打分

第二路信号更直接：把 CoT 按句切分，每句用 HHEM-2.1 打 ±1 分（忠实 +1，不忠实 -1），这个奖励只广播给该句对应的 token。但作者发现单纯这样做会导致**奖励作弊（reward hacking）**——模型学会疯狂输出"正确但没有信息增量"的车轱辘话（比如反复用不同措辞复述同一个事实），因为这些句子在 PRM 看来都是"忠实的"，能白嫖高分。

为此加了两个惩罚项：

- **信息增量惩罚（Information Gain Penalty）**：对每句话，找到它语义上最相似的**前一句**作为"锚点"（用 bge-small-en-v1.5 embedding 计算相似度），如果相似度超过阈值 α 且 PRM 判定为忠实，就记一次"围绕该锚点的重复"。惩罚只累积在真正被反复复读的锚点句上，而不是像一个更朴素的做法那样——对每句话都去累加它与**所有**前面句子的相似度超阈值次数。论文在附录 A.11 专门做了对比：朴素做法会让长 CoT 的惩罚爆炸式累积（71.14% 的长序列会被过度惩罚），而基于锚点的做法明显更稳定、更公平。这是一个我觉得写得比较讲究的细节。
- **重复惩罚（Repetition Penalty）**：基于 n-gram 重复率的传统惩罚项，防止模型陷入字面上的复读循环，同时也能加速训练早期收敛。

最终，每个 token 的奖励 R_cot 按规则组合（答案错则整条 CoT 统一给 outcome 惩罚；答案对则按句子的 R_fact − R_inf − R_rep 组合），并做了裁剪防止过度惩罚。训练用带 KL 项的 GRPO loss，token 级 advantage 通过组内 token 基线归一化（附录 A.2）。

## 3. 实验设置

- **任务**：开卷问答（Open-Book QA），给定上下文 C 和问题 Q，模型输出 CoT + 答案。
- **数据集**：SQuAD、NewsQA、TriviaQA、NQ（Natural Questions）、HotpotQA。训练数据是从 HotpotQA 和 2WikiMultiHopQA 里采样的 8,000 条（沿用 FSPO 的设置）。
- **模型**：DeepSeek-R1-Distill-Qwen-1.5B（DPSK-1.5B）、Qwen3-0.6B、Qwen3-1.7B 作为主要实验对象；DPSK-7B、Qwen3-8B 作为同系列大模型参照。
- **指标**：
  - **Acc**：答案对 gold answer 的 F1。
  - **Faith（Faithful Rate）**：不依赖 gold answer，用 LLM-as-judge 判断答案是否被上下文支持。
  - 分析用的辅助指标：CoT Faith / Key CoT Faith（CoT 层面的忠实率）、HR / KHR（Hallucination Rate，幻觉率，是 Faith 的反向表达）。
- **Baseline**：SFT（拒绝采样挑正确答案做微调）、KD（用 Qwen3-32B/DPSK-32B 做教师蒸馏）、Self-Refine（自我反馈迭代，最多 3 轮）、vanilla GRPO（纯 outcome reward）、FSPO（Li & Ng 2025，粗粒度步骤打分）。为了公平，所有 baseline 都给 16 条 rollout，对齐 FaithRL 因 DTR 而产生的有效采样量。

## 4. 主要结果

- **全面超越所有 baseline**：三个 SRM × 五个数据集，FaithRL 平均比最佳 baseline 提升 **Acc +7.29%、Faith +1.73%**。
- **一个很有说服力的反差实验**（Figure 3）：把 GRPO 训练过程中的 Answer Faithful Rate 和 CoT Faithful Rate 分别画出来，会看到 **答案层面的幻觉率在下降，但 CoT 层面的幻觉率在同步上升**——非常直观地证实了"outcome-only reward 会滋养过程幻觉"这个核心论点。FaithRL 则在两个层面都同步提升。
- **对抗攻击下差距被放大**（Table 5）：用第 3 节的攻击方法构造对抗问题集后，所有方法性能都大幅下降，但 FaithRL 相对 GRPO 的优势被进一步放大——论文给出的数字是 Faith 提升幅度扩大了 271%（正常条件下领先 8.77%，攻击条件下领先 23.80%）。这从"下游鲁棒性"的角度佐证了：只优化答案正确率的模型，其"正确"更脆弱、更容易被针对推理漏洞的问题击穿。
- **消融（Table 4，DPSK-1.5B）**：去掉 DTR 重采样，Faith 从 79.77 掉到 67.19（论文表述为约 15.77% 的相对下降），是所有组件里影响最大的；去掉信息增量惩罚，在复杂任务 TriviaQA 上掉得比较明显（提示这个惩罚项对"逼模型认真推理而不是灌水"确实有用）；去掉重复惩罚，Acc 掉幅最大（54.65 vs 62.28）。
- **效率**：因为 DTR 会跳过已验证忠实的前缀、只重新生成分叉之后的部分，Qwen3-1.7B 上单样本平均生成 token 数只有 vanilla GRPO 的约 1/8（231 vs 1805），对应训练总耗时 29.28 GPU 小时 vs GRPO 的 35.59 GPU 小时（A800）。但 **DPSK-1.5B 是个例外**：FaithRL 总耗时反而比 GRPO 更长（32.92h vs 23.52h），作者将其归因于 DPSK-1.5B 触发信息增量惩罚（即触发"重复灌水"检测）的比例明显更高，说明这个模型本身奖励作弊倾向更强，需要更多修正性重采样。
- **泛化到其他任务**（附录 A.9，仅 DPSK-1.5B）：在 MATH-500（71.80→78.40）、GSM8K（75.60→85.80）、CommonsenseQA（35.40→38.60）、HaluEval-QA（45.90→50.10）上都优于 base 和其他 baseline；但在 TruthfulQA 上被 KD 反超（KD 41.14 vs FaithRL 39.71）。

## 5. 我的评价

**做得好的地方**：

1. **问题定义和动机铺垫非常扎实**。第 3 节不是简单说"小模型容易幻觉"，而是层层递进：规模对比 → CoT 比答案更容易幻觉（还专门设计了逐句消融去定位"关键推理路径"，排除无关过渡句的干扰）→ 攻击实验证明这种幻觉是有实际危害的、不是无伤大雅的噪音。这条论证链条让"为什么要做 step-level 而不是 outcome-level"这件事显得非常必要，而不是拍脑袋加了个模块。
2. **DTR 这个设计挺巧妙**。不需要单独训练一个能给出精确步骤级 value 的 PRM，而是用一个现成的幻觉分类器做"检测器"，配合重采样机制**隐式地**导出步骤级奖励，还顺带解决了"信息不够精确的 PRM 怎么用"和"减少重复采样、节省算力"两个问题，一举两得，附录里还给了这套等价性的推导。
3. **对 reward hacking 有真实的工程意识**。信息增量惩罚的"锚点"设计以及和朴素方案的对比实验（附录 A.11）说明作者不是随手加了个反作弊项就完事，而是真的观察到了具体的失败案例（附录 A.12 给出的例子里，模型生成了大段语义重复的"车轱辘话"来骗高分），并针对这个案例做了细致调优。

**局限性（论文自己承认的 + 我看到的）**：

论文自己在 Limitations 里坦承了三点：(1) 目前只验证了开卷问答，尚未在对话、长文写作、工具调用、代码推理、多模态推理等更开放的任务上验证；(2) 忠实度和 CoT 幻觉的评估很依赖 LLM-as-judge，判官本身也可能有偏差和幻觉；(3) 只研究了小模型（0.6B～1.7B），没探索这套方法在更大模型上是否依然有效。

我自己读完之后，觉得还有几点值得追加关注：

- **PRM 的可靠性是整个方法的命门，但验证得不够充分**。HHEM-2.1 是一个现成的、没有针对这个任务专门微调过的幻觉分类器，论文只在 **HotpotQA 一个数据集、DPSK-1.5B 一个模型**上招了几个学生标注了 200 条样本做了人工对齐验证（recall 83.25%、precision 86.14%、F1 83.59），然后就把它当作**跨 5 个数据集、跨 3 个模型家族**通用的奖励信号来用了。~15-17% 的判断错误率，在 RL 训练里是会被不断放大和利用的噪声源，这个泛化缺口（从单一小规模人工验证，到全面部署为奖励信号）我觉得是这篇论文比较薄弱的一环。
- **"答案正确"这个 Acc 指标本身在 baseline 对比里出现了一个反直觉现象，论文没有充分解释**。Table 3 里，vanilla GRPO 的 Acc（F1）经常显著低于 SFT、KD 这些非 RL 的 baseline（比如 DPSK-1.5B 上 GRPO 的平均 Acc 只有 38.71，反而不如 SFT 的 47.27），但 GRPO 的奖励函数明明就是"答案对不对"本身。论文把这个现象归因于 GRPO 会滋养 CoT 幻觉，但没有直接解释"一个直接优化 F1 的方法为什么在 F1 上打不过没有用 RL 的 SFT/KD"——这多少说明 GRPO baseline 本身可能存在训练稳定性或调参公平性的问题，值得单独澄清，否则容易让人怀疑 FaithRL 相对 GRPO 的部分优势，是不是也部分来自 GRPO baseline 没调好。
- **任务场景仍然偏"有干净的、简短的、可核对的上下文"这一类**。开卷 QA 里，"忠实"有非常清晰的操作定义——句子能不能在给定段落里找到依据。但很多真实场景（长文档 RAG、多轮对话、agent 调用工具后的推理）里，"依据"分散在很长的历史或多个工具返回结果里，用逐句 embedding 相似度 + 一个通用幻觉分类器去做验证器，是否还成立，这篇论文完全没有触碰。附录 A.9 的泛化实验虽然覆盖了数学、常识、真实性等任务，但本质上还是"有明确 ground truth 可判定"的题型，没有触及真正开放式生成的场景。
- **序列长度设定比较保守**。训练时 prompt+response 上限只有 2048 token，相对当下动辄上万 token 的长推理链模型，DTR 的截断重采样机制在更长链条下的行为（要重采样多少次、树会分叉多深、算力代价如何）还是未知数。

## 6. 还值得进一步探索的问题

1. **PRM 质量对最终效果的瓶颈到底有多大**：换一个更强、或者针对"忠实性判断"专门微调过的验证器（甚至用多个判官做 ensemble/self-consistency），看 FaithRL 的上限能不能进一步打开；也值得研究当策略模型能力逐渐超过 PRM 的判断能力时，这套方法会不会失效或者反噬。
2. **从"单段上下文"扩展到更真实的知识来源**：长文档 RAG、多文档问答、agent 工具调用轨迹——这些场景里"忠实"要对齐的东西不再是一段干净的文本，DTR + 逐句 PRM 这套机制怎么改造才能适用，是个开放问题。
3. **规模律（scaling）研究**：在更大范围的模型尺寸（0.6B 一直到 30B+）上跑同一套训练配方，看步骤级忠实度奖励的边际收益在哪个尺度开始消失，以及它和以能力为导向的 RLVR（比如数学、代码任务的正确性奖励）叠加使用时是相互促进还是相互干扰。
4. **减少对 LLM-as-judge 的依赖**：更大规模的人工标注（不止 200 条、不止一个数据集），或者用多个独立判官模型互相校验，量化一下"判官偏差"到底给论文的核心数字（Faith、HR/KHR）带来了多大的方差。
5. **信息增量惩罚会不会误伤有用的"自我复核"行为**：现在很多推理模型会通过重新表述、二次验证来提高准确率（这也是长 CoT 推理模型常见的有效模式），一个基于语义相似度的"反重复"惩罚，理论上有可能把这种有益的复核和纯粹灌水的车轱辘话一起压制掉，值得专门做个案例分析或者消融来确认没有误伤。
6. **长链条下 DTR 的可扩展性**：把最大长度从 2048 token 放大到今天主流长推理模型的量级，观察截断重采样的触发频率、树的分叉深度、以及由此带来的额外算力开销是否还能维持论文里报告的"更省 token"的结论。
